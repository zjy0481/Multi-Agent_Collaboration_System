## 1. 历史输入对具体决策错误有多大影响？

团队消息 `seq=187` 撤回了与本目标无关的缺陷说法；`seq=282` 和 `285` 仍在讨论不同 QA 报告应引用哪一版。单次输入很长，但当前审批线索的呈现方式、过期消息的抵达顺序、模型自身判断也可能产生类似表现。现有轨迹无法证明某次误判由历史长度造成。[历史输入问题 #27](https://github.com/zjy0481/Multi-Agent_Collaboration_System/issues/27) · [证据版次问题 #24](https://github.com/zjy0481/Multi-Agent_Collaboration_System/issues/24)

**最小验证。** 选取一条错误判断前的可读快照，固定角色、审批事实、模型设置和可用工具。对照原历史与保留相同授权事实的精简历史，重复观察能否选出正确的审批版本；分别记录误选和无法判定的次数。

## 2. 等待、工具执行、推理与重试分别增加了多少墙钟时间？

`comparison-timing.json` 给出五段计时合计 5,731.392 秒；三项首次全部获批到终态的自然时差为 2,037.683 秒。模型请求、等待执行槽、其他角色工作可同时发生，这两个数字不足以分配各机制的耗时占比。高缓存命中也不足以推算账单。[调度问题 #25](https://github.com/zjy0481/Multi-Agent_Collaboration_System/issues/25) · [回合预算问题 #26](https://github.com/zjy0481/Multi-Agent_Collaboration_System/issues/26)

**最小验证。** 先按角色和投递对齐创建、领取、请求、工具回执及审批时间，只累加关键路径上互不重叠的区间，单列停机和无法定位的时间。若要估算某一改动节省的时长，再在可比任务下单独改变该因素。费用需要供应商的相应计费依据。

## 3. 传输异常和供应商差异是否改变了完成结果？

剔除发题前请求、计入终态后的确认请求，本轮有 13 次 HTTP 429、22 次出站请求未记录 HTTP 响应。日志覆盖几次分段停机，未收到响应有多种可能。旧对照中的基线、预算、端点或操作介入不同，无法据此判断换供应商能否消除本轮失败。

**最小验证。** 先把无响应请求与客户端异常、重试和停止时间逐笔对齐，无法归属的保留未知。若比较供应商，固定基线、角色、题面、预算、停止条件和介入规则，交替重复运行并记录端点负载的不可控差异。

## 4. 无人工介入时，团队是否会自行结案？

**最小验证。** 从相同的“构建复审已通过、尚未结案”快照分别继续，固定恢复方式与观察窗口，对照无补充、普通补充、正式更正三种情况。记录消息是否被消费、是否取得正式终态和截止时的待办；到期仍未完成只说明该窗口内未收敛。
