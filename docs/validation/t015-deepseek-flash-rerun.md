# T015 使用 DeepSeek Flash 复跑五道官方样例

2026-11-23 使用 DeepSeek 官方 Chat Completions 端点 `https://api.deepseek.com` 和别名 `deepseek-flash`。该别名对应 DeepSeek-V4.1-Flash-1017。真实工具回执经两步调用验证，第二步用第一步返回的值作答。测试进程从系统变量 `ds_apikey` 注入凭据。运行环境采用 Python 3.14、Docker `collaboration-sandbox:local` 与本机 SearXNG。[官方模型说明](https://api-docs.deepseek.com/quick_start/pricing/) · [运行命令](../../scripts/t015/README.md)

沿用上一轮的五道未通过题。三个场景并行，新闻和基金每组在同一团队按顺序布置两题。用户布置保留官方文本，核对入库消息 SHA-256。每题名义窗口 20 分钟，动作仍在执行或窗口结束前 45 秒内产生新产物时最多追加 75 秒。运行器模拟澄清答复，并按上限恢复符合条件的回合。观察窗口结束时保留未完成记录。[上一轮 HKGAI 记录](t015-second-fix-rerun.md)

## 修复验证

- **#10 澄清恢复。** 组合回归通过正常发问和答复复现澄清投递在完成一笔工具调用后超时。操作者通过实际重试接口恢复，同一个回合保留原答复与工具回执，已完成动作没有重复执行。基金第一题真实实跑中的澄清投递触及步数限制，运行器提交检查点恢复并收到 HTTP 202。[组合回归](../../tests/test_t015_clarification_retry.py)
- **#11 请求诊断。** 记录每次尝试耗时、状态和供应商返回的 token 用量。`COURSE_API_TIMEOUT` 可配置，本轮为 120 秒。网络日志没有分离服务端排队和模型生成，也没有用总耗时直接推导 TPS。[模型适配器](../../collaboration_runtime/model.py)
- **#12 固定输入。** 操作者在布置时按负责人声明必需已发布版本。服务端验查参与方权限及委派输入。软件题实跑时首次漏绑快照，提案被拒绝，随后完成绑定。冻结版本 `48ea70e2bbb24b358dc0d6f98d0a7b72` 用快照 `7ad460f5bfce42d18a44ceda11234b02` 做独立 Docker 复算。全范围 3 笔活跃、210 分钟、1 笔取消，四个日期范围的总计、逐房间和峰值均一致。浏览器用 Docker 捕获的响应驱动实际冻结版页面，验证日期选择、表格和四个图表更新。原 T1 的预约库未留存。该快照由已验收的 T1 应用通过预约 API 录入明确标记的样本后生成。此处证实看板功能与指定快照的交接，历史 T1 数据连续性需另行取证。[交接回归](../../tests/test_delegation.py)
- **#13 原文跳转。** 对已授权检索结果使用有限次公开 HTTPS 跳转，每一跳重新验证并连接到经验证的地址，保存最终 URL、链路和原文摘要。覆盖成功跳转、拒绝目标、403、循环与限制用例。[来源回归](../../tests/test_source_evidence.py)
- **#14 和 #15 审稿和进度。** 对明确的提交、派工、就绪和退回事件提供具体操作指引。审稿仍依赖主审核对当前提交与原文，结案仍由 Lead 按已有业务条件处理。[调度引导](../../collaboration_runtime/scheduler.py)

最终完整回归启用 `RUN_DOCKER_TESTS=1`，180 项通过、6 项按联调开关跳过。JUnit 文件保存在原测试机的 `.tmp/t015-ds-final-regression.xml`。实跑的原始日志、获准产物和报告保存在原测试机的 `.tmp/t015/deepseek-flash-1017-five-20261123/`，目录相对于运行该版本的工作树。

## 运行诊断

- 五题合计登记 12 项任务、产生 15 次正式提交、14 次审查和 194 个新发布版本。发布文件的 SHA-256 均与记录一致。36 笔恢复请求返回 HTTP 202。五题均出现了两个重叠角色回合各有写入、编辑或发布成功的样本。同一目标还需同时满足至少两名正式委派角色各交付、主审通过和 Lead 结案，软件题只有一名负责人正式提交。
- 2,388 次成功请求均有供应商返回的用量。成功请求耗时中位数 4.31 秒，P95 24.00 秒，有 21 次超过 60 秒。另记录 12 次传输错误、9 次 429 及 89 次 402。新闻 2 和基金 2 窗口末段收到 HTTP 402，单独发出的最短探测请求也返回 `insufficient_balance_error`。新闻 1 和基金 1 在余额错误发生前就达到了观察窗口，检索、取证和审查的缺口可单独核对。[DeepSeek 错误码](https://api-docs.deepseek.com/quick_start/error_codes/)
- 此轮五题实际保存 30 份新原文。受控测试验证了合法跳转后的正文和来源链，五题未观测到成功跳转取证。新闻核查判断以及课程要求的正式并行结案仍需独立复验。调整了运行时代码、端点、读取超时和复跑器，无法单独归因于模型速度。[HKGAI 基线](t015-second-fix-rerun.md)
