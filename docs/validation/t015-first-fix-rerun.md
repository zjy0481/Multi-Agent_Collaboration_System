# T015 首批修复后官方六题复跑


本文中的 `.tmp` 路径指原验收机器的本地记录，仓库不会包含这些文件。可按本地环境配置指南运行仓库内测试。
2026-11-23 使用 HKGAI `t2_hkgai-v3_fp8_1m_e7`、Docker 沙箱和本机 SearXNG 实跑三组官方样例。三个场景并行，每组沿用同一个四角色团队连续执行两道题。逐题校验 SQLite 中的用户消息与官方 `text` 原文及 SHA-256 一致。测试操作者对实际提出的问题提供模拟用户答复。每题上限为 900 秒，未结案时由操作者取消并保留取消前状态。基金和新闻组在第一题未完成的情况下继续第二题。 [官方样例](<../../test samples/README.md>) · [T015 工单](../plans/agent-collaboration/revisions/r0003/tickets/T015.md)

## 修复与回归

- 模型请求对超时、连接错误和指定临时 HTTP 错误自动重试至多两次，已经获得回执的工具不会重新执行。若仍失败，本机操作者可通过 `POST /v1/sessions/{session_id}/turns/{turn_id}/retry` 恢复原回合。回归覆盖工具单次执行、权限、互斥恢复和已结束目标。 [恢复实现](../../collaboration_runtime/api.py) · [回归用例](../../tests/test_model_recovery.py)
- 任务投递中的群消息继承目标归属，结案时清理该目标的关联投递。调度优先领取可恢复回合、新布置和待审提交。目标内的回合保留同目标历史，后续布置可以通过公开产物与经验工具使用前题成果。 [调度实现](../../collaboration_runtime/scheduler.py) · [回归用例](../../tests/test_goal_delivery_scope.py)
- 指定审查人收到确切提交版本、证据及审查动作，验收条款随任务投递传入。真实六题启动后又补上旧任务修订通知的保护，当前任务已升版时，旧通知不会再附带审查指引。该保护由新增回归覆盖。 [审查实现](../../collaboration_runtime/delegation.py) · [回归用例](../../tests/test_task_results.py)

最终代码开启 `RUN_DOCKER_TESTS=1` 的全量回归 **166 项通过，6 项按联调开关跳过**。JUnit 位于 `.tmp/t015-final-review-docker.xml`。六题使用启动时的代码快照，`run.json` 保存源文件 SHA-256。与最终代码相比，唯一有差异的运行时源是后来补上旧修订保护的 `delegation.py`。

## 剩余阻塞与证据

- 真实日志记录 35 次自动重试，仍有 6 个回合最终因请求超时失败，另有 8 个回合触及模型步数上限。人工恢复入口在回归中验证，本轮六题由自动调度推进，操作者没有代模型重试回合、派工、审查或结案。
- 运行中默认 SearXNG 引擎曾报告限流或超时。单独验证 Bing 引擎可返回结果后，在仅监听回环地址的本机 SearXNG 启用了 Bing 并重启服务。更改写入 `.tmp/searxng/settings.yml`，原配置保存在同目录。首轮与本轮的时间预算、并发执行方式和检索状态存在差异，整体成果变化不能单独归因于某一项代码修复。
- 机器汇总在 `.tmp/t015/official-first-batch-20261123/summary.json`。同目录各场景保存两题的消息、投递、工具回执、产物版本、报告、审查和终态。已对发布副本校验 SHA-256，副本位于 `.tmp/t015/official-first-batch-published/`。独立软件检查见 `.tmp/t015-software-independent-v3-20261123/output.txt` 和 `.tmp/t015-software-t2-draft-check/`。真实模型重试日志在 `.tmp/t015-first-batch-live.log`。
