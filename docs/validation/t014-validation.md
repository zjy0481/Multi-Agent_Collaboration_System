# T014 组合验收记录

集成基线为 `fa88192`，包含 T007 的历史分支、T010 的报告、T011 的本地审批和 T012 的跨题经验。使用临时 SQLite 状态、确定性模型与测试数据复跑组合场景，工作区隔离另由真实 Docker 回归验证。

2026-11-23 的最终回归开启 Docker 和本地 Git，结果为 **152 项通过、6 项按联调开关跳过**。JUnit 共登记 158 项，4 个新增 T014 场景全部通过。

## 联验发现与修复

当已有活动目标且另一条布置尚未登记时，后者的澄清原先借用活动目标的归属。用户撤回未登记的布置后，迟到回复仍会形成 `clarification.resume` 投递。修复后，结案、答复恢复和报告共用同一归属判定。显式引用链以原始布置为准，无显式引用链的工作沿用记录中的活动目标。已有问题无需更新数据库。回归确认迟到答复只归档，另一目标仍活动，待答时段冻结在撤回时刻。

## 复验

在仓库根目录运行以下命令，SQLite、测试产物与 Git 裸仓库放在每次新建的临时目录。

```powershell
$env:RUN_DOCKER_TESTS = '1'
$t014Run = Join-Path '.tmp' ('t014-evidence-' + [guid]::NewGuid().ToString('N').Substring(0, 6))
New-Item -ItemType Directory -Path $t014Run | Out-Null
python -m pytest -q --basetemp (Join-Path $t014Run 'cases') --junitxml (Join-Path $t014Run 'junit.xml')
```

浏览器夹具使用 `python tests/t014_workbench_fixture.py` 启动，监听 `127.0.0.1:18765`。程序打印临时 `fixture.json` 路径，内含本次测试的 reviewer 和 outsider 令牌。先以 reviewer 登录，打开「任务交付」中的 `T014 review fixture`，展开当前和历史提交，记录决定、版本和下载证据。再退出并以 outsider 登录，核对列表和直接下载是否按权限显示。夹具使用隔离的模拟工作区与合成审查证据。

真实 HKGAI 与 SearXNG 的既有联调采用 T013 验证记录。本轮 Git 验收目标为本地裸仓库，课程 GitHub 交付归 T016。依赖精确版本、上游来源与机制参照见 [组件来源与验证索引](../t014-components.md)。
