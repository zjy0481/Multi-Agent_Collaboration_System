# S003 私有执行、产物版本与审查

## 范围与需求来源

提供每个正式成员及助手的独立受控工作区、版本交接、Git 外部动作与主审验收。平台应用服务判断权限和业务状态，Docker 与 Git 完成各自执行能力。 [定稿需求](../../../../../grill_result/agent-collaboration/requirement.md#项目交付行为) · [运行时提交边界](../../../../../grill_result/agent-collaboration/runtime-contract.md#持久记录与提交边界)

<a id="workspace"></a>

## 执行空间和受控工具

- 宿主按团队和执行身份绑定独立工作卷，每个助手使用独立可写空间。建组或增员确认工作区就绪后才能将该身份投入调度。工作区准备可重试，同一身份复用登记的空间。Docker 使用非特权容器、受限挂载及 CPU、内存、时限。宿主保管模型、搜索和推送凭据。
- 文件工具和执行工具只作用于登记工作空间或准入的只读材料，校验路径实际落点和当前权限。支持读取、创建、修改和删除文件，以及运行代码与测试。搜索与资料获取使用宿主受控工具，记录来源和结果。工作区执行与宿主网络工具分别授权。撤权时已导入文件随对应执行范围停止向助手提供。
- 复用 Docker Engine 的执行、挂载和资源配置。可参考 OpenHands 的工作区生命周期。Git worktree 用于代码检出便利，由宿主管理共享仓库元数据，角色访问边界仍由容器、挂载和应用授权落实。 [Docker 资源限制](https://docs.docker.com/engine/containers/resource_constraints/) · [只读卷](https://docs.docker.com/engine/storage/volumes/#use-a-read-only-volume) · [OpenHands Docker](https://docs.openhands.dev/sdk/guides/agent-server/docker-sandbox) · [Git worktree](https://git-scm.com/docs/git-worktree)

<a id="external-actions"></a>

## Git 与真人批准

- 受控提交操作在获准工作区内形成 Git 提交。候选工具 `request_push` 接受仓库、目标 ref、提交 SHA 和请求键，持久化动作、原工具调用 ID、参数摘要和 `approval_id`，返回 `awaiting_approval` 回执并阻塞对应工作。该回执完成原工具调用，等待不占执行槽。真人在 `POST /v1/approvals/{id}/decision` 作决定，对同一动作写入审批状态和后续待办或拒绝通知。
- 宿主执行器按动作 ID 原子领取获批待办，发起前重新检查已批准摘要、当前工作范围及权限。完成、拒绝或待核对事件送达原执行会话，后续决策按动作 ID 读取回执，保留与初次工具调用的关联。请求重放返回相同审批及动作标识，决定重放复用同一执行待办。
- 先持久化已准备和已领取记录再执行网络调用。区分待批、拒绝、获批、执行中、成功、失败和结果不明。推送超时或已领取后重启时查询获准的远端 ref，保留可核对的实际状态。确切提交已可见时补回执，无法确认时保留待核对。终止后仅核对已发起动作。 [Git push](https://git-scm.com/docs/git-push) · [Git ls-remote](https://git-scm.com/docs/git-ls-remote) · [S002 恢复](S002.md#execution)

<a id="review"></a>

## 不可变发布、提交与审查

- `publish_artifact` 先完整保存并验证内容与摘要，再登记逻辑产物、不可变版本、内容位置、作者、权限、来源及适用工作范围。只有登记版本可读，未引用的暂存内容可安全清理。 `GET /v1/artifacts/{id}/versions/{v}` 与工具读取按精确版本检查权限，允许接收者导入获准副本，保留来源和实际导入版本。
- 正式负责人以当前任务修订调用 `submit_result`，绑定所交版本、验证证据、遗留问题及前次退回。写入后进入待验，通知主审、Lead 和派发者，同一收件人作用相同的通知去重。指定主审就该提交逐项对照约定，用 `review_result` 作通过或有证据的退回，退回写预期与复验项。过期修订、过期提交及冲突审查返回状态冲突。
- 重交沿用任务 ID，更换提交与产物版本。依赖旧版的下游进入待复核，输入绑定和旧审查可追溯，独立通过项保留。向 S001 提供当前有效验收及最终版本可读性，向 S004 提供提交、版本、审查与计数证据。 [S001 状态](S001.md#delegation) · [S004 指标](S004.md#metrics)

<a id="verification"></a>

## 规格验证

用两个工作区复现发布、授权读取和独立重现。核对第三成员无法读未发布草稿或宿主凭据、获准版本可读、命令超时有结果。先验证拒绝审批，再修改仓库、ref 或 SHA 检查重新审批，重放同一有效请求并模拟结果未知。走通模块 v1 退回、原任务 v2 重交、仅依赖旧版的下游待复核，以及旧验收无法成功结案。真实推送的验收依赖获准仓库及真人批准。
