# r0003 拆票与审阅

本修订按 [r0002 业务确认](../r0002/review.md) 拆票。容量按用户确认的两张票。相对区间和依赖的主要位置是 [计划摘要](plan.md)，估算包含实现、验证及常规整改。

<a id="external-conditions"></a>

## 外部条件

- E001 和 E002 涉及课程认可模型的实际端点、配额与检索来源，影响真实联调。
- E003 涉及一次 GitHub 真实验收。获准的验收仓库、目标 ref、提交和真人批准需要在实际运行前具备。
- E004 涉及课程闭集的发放和运行安排。E005 涉及课程组对基金题正式提交格式和实际提交安排的决定。 [课程条件](specs/S004.md#外部条件)

## 拆分与合并候选

- T001 保留从角色输入到可用团队的完整行为。容器文件操作与版本交接在 T005，初始隔离工作区准备属于 T001，因为建组和动态增员都要验证就绪后生效。
- T004 和 T008 分开。草案同版确认、并发登记可在有版本交付前验证，T008 用正式任务与不可变产物核查局部返工。
- T011 与 T016 分开。用可控远端验证审批重放和恢复，再用获准 GitHub 目标取得真实回执。T013 独立承接课程端点和检索的外部条件。
- T014 保留独立组合验收，验证单票测试覆盖不了的权限投影、恢复和冻结接缝。T015 验证公开样例，T017 验证课程闭集，二者在同一平台基线上分别留下运行记录。
- 若 T013 与 T016 在相同验收环境出现实际资源互斥，再登记该资源；本次容量为两张票，外部资源何时可用仍按各自门槛。

<a id="decision-scope"></a>

## 确认范围

任务写入能力、必需交付和队列推进采用用户对 r0002 的决定。该决定见 [r0002 确认记录](../r0002/review.md#business-decisions)。

<a id="breakdown-acceptance"></a>

2026 年 11 月 22 日（上海时间），用户确认 r0003 的拆票和相对排期。确认覆盖 18 张票、票间依赖、最多两张票并行的容量，以及外部条件对应的待定区间。 [计划摘要](plan.md) · [修订记录](revision.json)

<a id="chain-review"></a>

## 独立全链审阅

同一名只读审阅者沿用 r0002 的规格审阅，对照相同规格复核新票接缝，采用 tickets-review 检查交付、覆盖和验证归属，采用 plan-review 检查全图、容量及外部门槛。首次发现六处问题，修订后由同一人定点复审并确认关闭。

| 首审发现 | 已复核的修订 |
|---|---|
| 消息待办和工作启动缺少可验证交付 | T002 负责消息待办持久化与目标登记。T003 用受控夹具验证独立工作保持就绪，T014 验证真实独立执行。T006 消费 T002 的待办。 [T002](tickets/T002.md) · [T003](tickets/T003.md) · [T006](tickets/T006.md) |
| T011 的前置 Git 能力缺少提供者 | T005 提供隔离执行和受控命令，T011 实现 Git 操作。 [T005](tickets/T005.md) · [T011](tickets/T011.md) |
| 终态和报告用例有遗漏 | T009 核对失败、超时与终止。T010 核对对应分类、原因和时间。 [T009](tickets/T009.md) · [T010](tickets/T010.md) |
| 历史分支与授权验收范围不足 | T007 验证直接答疑和父代理采用或退回。T014 核对全部授权投影面及正反例。 [T007](tickets/T007.md) · [T014](tickets/T014.md) |
| 缺少开源接入证据的汇总责任 | T014 收集实际采用版本、源码、许可证、参照机制和验证，T013 提供真实联调证据。 [T013](tickets/T013.md) · [T014](tickets/T014.md) |
| 最小网页交付证据缺少验收 | T008 验证交付版本与审查证据的读取，T014 在整合版本复核。 [T008](tickets/T008.md) · [T014](tickets/T014.md) |

复审确认依赖无环，派生区最大并发为 2，外部门槛仍正确传播。计划脚本的结构和快照检查通过。 [计划摘要](plan.md) · [审阅输入哈希](revision.json)
