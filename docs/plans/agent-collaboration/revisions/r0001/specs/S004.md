# S004 个人经验、评测与课程场景

## 范围与需求来源

保存个人经验及采用证据，并从持久业务事实生成可重算的评测和按权限导出的报告。负责组织贯通团队、运行时、执行与交付的组合验收。 [定稿需求](../../../../../grill_result/agent-collaboration/requirement.md#评测与交付边界) · [课程要求](../../../../../raw/basic_requirement.md) · [官方样例](<../../../../../../test samples/README.md>)

<a id="memory"></a>

## 个人经验与跨题交接

- 每个正式成员的经验有独立所有者。通过 `record_lesson` 写入经验正文、证据引用、适用和失效条件。检索先按所有权、显式交接和来源权限筛选，再匹配内容。普通 SQLite 查询可满足首版检索，FTS5 仅在样例命中和隔离验证后考虑。 [SQLite FTS5](https://www.sqlite.org/fts5.html)
- 经验正文默认作者可读。其他成员及助手可读取显式交接的条目，助手访问受当前委托和材料来源约束。保存检索记录、采用的后续行动及观察结果，允许观察到无变化或失效。报告面向更大受众时重新按来源投影。
- 第二题沿用同一团队、获准的材料和长期分工，使用新的目标及指标。跨题交接记录来源目标、版本或经验、接收者和用途。软件组必须显式交接第一题的系统版本和真实预约记录。新闻组针对新主张取证，基金组按新受众重新确定表达。 [S001 授权读投影](S001.md#shared-contract) · [S003 版本交接](S003.md#review)

## 评测事实、计算与报告

| 记录 | 候选实现契约 |
|---|---|
| 原始布置 | 报告以原始布置消息 ID 为稳定键，使用其服务端入库时间。登记补上目标 ID 和排队状态，登记前明确终止也留下可导出的事实。普通交流以及同目标补充不增加目标数。 |
| 目标完成率 | 分母为评测范围内的唯一布置，分子为按有效条件验收并交付的目标。失败、超时、终止及尚未完成的目标分别列出。 |
| 子任务完成率 | 按目标冻结已生效任务 ID 和当前验收证据，分子取冻结时符合当前条件的已通过任务数，分母取全部已登记的唯一任务数。返工、历史修订、未接受草案和助手内部工作不另计。分母为零记不适用。 |
| 时间与冻结 | 端到端耗时从布置到交付或终止，包含登记前澄清和排队。记录并单列真人等待区间。S001 进入终态时从 S003 当前有效验收写入冻结集合、原始计数、指标版本和时间。迟到结果保持冻结事实。 |
| 报告及导出 | `GET /v1/goals/{id}/report` 导出获准目标。候选汇总入口 `GET /v1/teams/{id}/evaluation/report` 以明确的评测对象集合为范围，通过经授权的 `assignment_ids` 指定原始布置消息，去重并返回集合摘要、各目标结果、总目标原始计数、各项端到端耗时和真人等待区间。登记前终止直接按原始消息查询终止事实。数据从一致的读视图生成，导出保留可见对话、版本、审查、模型、模式、失败及经验采用引用。外部评分另列来源。读者仅能重算有权限的报告范围。 |

成功和失败都要可回溯到业务记录。指标计算使用身份与审查回执，模型可辅助说明观察，但不负责裁定平台完成率或填入未观测数据。真实端点运行、回归和外部评分各自标记。

## 跨规格验收责任

| 验收组合 | 所需证据 |
|---|---|
| 会话与权限 | 覆盖旧回合分支、私聊隔离、父子并行、首次协商、过期草案、两个问题及重启。用一次允许读取和一次禁止读取核对快照、模型输入、附件、检索、回放、经验和导出。 |
| 工具与交付 | 真实课程模型完成两步依赖工具调用。两位成员在独立空间按版本交接，局部返工后重验受影响下游。批准拒绝、参数变化、推送未知及复查回执能分别定位。 |
| 终态与计数 | 在同一报告中模拟三个用户布置，分别已交付、已失败和登记前终止，重算总目标 `1/3`。在失败目标中模拟两项通过、必需的一项未通过及一份未确认草案，包含返工后按任务 ID 重算子任务 `2/3`。按入库时间及终态验证登记前澄清、排队、真人等待和端到端耗时。记录迟到结果与冻结，另观察下一排队目标激活。 |
| 三组连续题 | 导入原角色配置，每组在同一团队连续运行两题，分别保留耗时、对话、产物、验收引用及经验的采用结果。演示一次同伴证据改变后续行动的实际记录。按初步设计第 8 节检查六题产物。 [六题验收](../../../../../preliminary-proposal.md#8-三组场景怎样验收) |
| 正式课程验收 | 用课程指定模型和闭集产生中期及期末评测结果，汇入性能与失败分析、记忆演进、架构文档、团队实际贡献历史及课程展示材料。 [课程提交要求](../../../../../raw/basic_requirement.md) |

## 外部条件

样例基金第二题准备 HTML 演示和 Markdown 内容稿，正式提交格式由课程组确认。闭集输入、发放时间、提交日程和端点配额影响正式运行。样例与离线回归可独立设计，正式结果待实际运行。 [定稿需求 U-001、U-002](../../../../../grill_result/agent-collaboration/requirement.md#评测与交付边界)
