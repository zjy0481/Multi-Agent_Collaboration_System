# S001 团队、消息与任务协作

## 范围与需求来源

提供可操作的本机工作台。从导入角色到建组、接收用户目标、协商委托、处理真人问题并交付或终止。定稿需求中的协作与权限规则优先，业务对象以领域模型为准。本规格维护 HTTP、模型工具、持久待办和授权读投影共享的约定。 [定稿需求](../../../../../grill_result/agent-collaboration/requirement.md) · [领域模型](../../../../../grill_result/agent-collaboration/domain-model.md) · [运行时对接设计](../../../../../grill_result/agent-collaboration/runtime-contract.md)

## 公共写入与读取契约

| 接缝 | 候选实现契约 |
|---|---|
| 调用身份 | HTTP 入口从已验证的本机用户会话取身份。模型工具入口从执行会话和运行代次取正式成员或助手身份。处理器接收 `team_id`、调用者、操作名、请求键和参数。目标、任务和产物按所属团队解析。角色标识与所有权从宿主记录得到。 |
| 写入回执 | 同一调用者、团队、操作和请求键对应一个规范化参数摘要及回执。相同参数重放返回原回执，参数异义返回 409。回执至少标识业务对象、发出的事件和适用的版本。重复请求仍检查调用者当前对回执的读取权限。 |
| 错误语义 | 422 用于参数结构或值无效，404 用于不存在或不可读的对象，已获读权但无操作权限时返回 403。过期修订、状态冲突和重复键异义返回 409。工具错误返回同一业务原因，并归还原模型调用 ID。 |
| 一致性边界 | 在 SQLite 短事务内检查权限、当前范围及预期修订，原子写入业务记录、回执、事件和待投递项。待投递以事件、收件人和用途去重。网络、模型、长命令和文件复制在事务外进行。事务提交后才返回写入成功。 |
| 可见性 | 每次读取须同时满足对象权限及所引用来源的权限。群内读者与执行收件人分别记录。正文、附件、摘要、工具结果、检索命中和导出使用同一读取规则。扩大受众时显式交接允许的材料或概要，保留授予范围和来源引用。 |

静态网页采用 FastAPI、原生 SSE、浏览器 `fetch` 与 `EventSource`。快照返回同一读视图下的可见状态和事件游标。初次连接使用 `after`，重连以同一流的 `Last-Event-ID` 为续读位置。服务端逐条投影可见事件，浏览器按事件序号去重。游标过期时请求新快照。网页提供团队列表、群聊和双方私聊、待答问题、交付详情和认可证据。 [FastAPI SSE](https://fastapi.tiangolo.com/tutorial/server-sent-events/) · [浏览器 SSE 规范](https://html.spec.whatwg.org/multipage/server-sent-events.html#the-last-event-id-header) · [SQLite 事务](https://www.sqlite.org/lang_transaction.html)

## 建组、消息与人工决定

- `POST /v1/teams` 支持角色表、原始 ID 和角色提示正文。格式或引用错误携带原文件位置，校验失败时团队不可用。识别已有 Lead 并记录依据。缺 Lead 时过渡代理用一次有界建组会话创建稳定 Lead 身份，交接后结束。完成团队契约、主会话和工作区准备后进入可用状态。增员先固定职责、写权限、执行空间与主会话，再提交契约修订并公布。原角色提示保留在身份档案。工作区准备与重试见 S003。 [官方角色文件入口](<../../../../../../test samples/README.md>) · [执行空间](S003.md#workspace)
- `POST /v1/teams/{id}/messages` 接收请求键、正文、群聊或双方线程及可选点名与引用。服务端按引用有效问题、点名、未点名真人的 Lead 顺序选择主要行动人。广播进展可读但不自动唤醒。同一目标补充关联既有布置，明确另起的目标排队。同一团队一项活动目标。 [OpenClaw 定向唤醒参考](https://docs.openclaw.ai/channels/groups)
- Lead 用 `register_goal` 关联用户原始布置。即使目标尚未登记，`ask_human` 可引用原始消息，并持久化提问者、答复人、线程、影响范围与阻塞项。用户自由文本引用问题，首次有效答复和解除对应阻塞同事务写入。其余阻塞仍在时继续等待，释放执行槽。用户修正旧决定后，按已有引用通知负责人确认影响，独立工作继续。
- Lead 写入长期分工契约时携带预期版本、变更依据、牵头与协作边界。持久记录以团队和版本唯一，保留前版引用，公布事件与新版本一起提交。建组写初版，增员就绪后更新职责编排。已生效任务的承诺有独立修订。
- `close_goal(goal_id, expected_revision, final_versions)` 由 Lead 发起，核对目标仍有效、必需交付已通过、相关阻塞已解除且用户可读最终版本。候选共享终态处理器接收 `goal_id` 或原始布置消息 ID、适用的预期修订、稳定请求键、结果和原因。用户发起终止写入 `cancelled`，保存用户给出的原因，无说明时记录主动终止。Lead 可在必需交付确认无法完成时提交 `failed` 及证据，宿主在持久运行事实确认不可恢复的故障或达到目标时限时写入 `failed` 或 `timed_out` 及依据。暂时中断及待核对继续走恢复流程。终态、服务端时间、原因、冻结事实和通知在同一事务写入。已终态或版本不匹配时以公共回执规则处理。团队有空位时，Lead 可将已登记且具备前置条件的排队目标原子激活。自动激活与队列顺序见待确认项。
- 目标结束时，在同一次终态写入中撤销该范围的未来待办、失去全部有效关联的待答项和未登记草案，并冻结评测记录。继续服务其他有效范围的事项保留其关联。迟到内容仅用于历史和已启动外部动作核对。 [报告冻结边界](S004.md#metrics)

## 委托、任务修订与交付状态

- 草案版本携带活动目标、交付物、输入版本、验收条件、派发者、拟负责人、主审、承诺方和依赖。首次草案使用有界协商关联，修订另带任务 ID 和基础修订。反提议产生新草案版本，每位承诺方确认的是具体版本。专家各自判断可附证据，单一建议由负责成员给出。
- 候选应用命令 `create_proposal` 接受目标、协商范围或任务及基础修订、拟议条款，返回草案 ID 和首个版本。`counter_proposal` 接受草案 ID、预期当前版本和新条款，生成新版本并单独收集确认。`reject_proposal` 由受邀承诺方拒绝其对应版本，`withdraw_proposal` 由该版提出方撤回。拒绝和撤回保留原因及历史，关闭对应未登记版本。正式成员可提出、反提议与确认，助手按委托提交草案或反提议材料。网页有需要时也调用同一应用命令。
- `POST /v1/proposals/{id}/confirm` 记录确认及尚待确认的人。`assign_task` 或 `update_task` 登记时重新校验全部承诺方、草案有效版本和当前基础修订。同一草案版本仅能登记一次正式变更，包括不同正式成员并发提交。负责人唯一，父子关系和前置依赖各自无环。首次草案在登记前不产生任务 ID 或评测分母。运行时可借鉴 LangGraph 动态分发和 DeepSeek Harness Team 的并发认领机制。 [LangGraph 分发](https://docs.langchain.com/oss/python/langgraph/workflows-agents#orchestrator-worker) · [DeepSeek Harness Team](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/team/agent-team/README.md)
- 首版导入的正式角色可在任务授权关系内调用 `update_task`，增员权限显式赋予。助手可交材料和草案，正式生效由有权成员执行。成功更新按权限在群内提及 Lead。交付提交和主审流程由 S003 定义，成功结案校验必需模块的当前验收、未解除阻塞与最终可读版本。 [提交与主审](S003.md#review)

<a id="pending-decisions"></a>

## 待确认的业务边界

| 对象 | 候选规则及影响 |
|---|---|
| 任务更新权 | 建议允许持有任务更新能力的派发者、负责人或 Lead 登记同版已确认的修订。主审按指派审查，若也需登记修订则依任务授权。改变负责人、主审或承诺条款时，保留被改变职责的既有成员和新承担者的确认。精确的参与角色及变更权限影响写接口和 403 验收。 |
| 必需模块 | 建议把必需交付作为目标验收条件中的显式条目，并关联适用任务和当前审查。由 Lead 组织确认，变更通过目标验收约定的修订留痕。影响目标结案判定和评测分子。 |
| 排队优先级 | 建议上一目标结束后通知 Lead，由 Lead 结合前置条件按排队次序激活下一目标。自动激活及是否允许改顺序仍需确认。影响并发领取、终态通知和计时用例。 |

## 规格验证

导入三个样例和一份无明显 Lead 的变长清单。验证输入错误行、过渡代理退出及运行中增员。用群聊、双方私聊、引用答复与点名冲突验证路由顺序。令两个任务同时待答，重启后只恢复已获答且无其余阻塞的任务。重放写入并并发登记同一草案，核对唯一任务和通知。用有权与无权读者比较快照、SSE 补发、模型上下文和导出，核对目标终止后迟到答复未重开工作。S004 的组合验收负责跨模块证据。 [组合验收](S004.md#scenario-validation)
