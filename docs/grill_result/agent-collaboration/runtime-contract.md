# 平台运行时对接设计

供后端、模型工具与网页联调使用。[详细需求](requirement.md)规定用户可观察的行为，[领域模型](domain-model.md)规定记录的含义与状态。

## 进程与数据归属

单机 FastAPI 进程承载 HTTP、工具处理器与后台调度。网页读取快照，用 SSE 接收增量。SQLite 保存控制状态、授权、会话历史、投递与工具回执。不可变产物目录保存实际字节。成员私有工作卷保存执行中的文件。宿主模型客户端调用课程端点，按会话归属记录每个工具调用和结果。每个活跃会话最多有一个正在推进的模型回合，独立分支有自己的运行槽。运行上限由本机 CPU、内存及课程配额配置。容量不足进入可见的等待队列。

| 入口 | 请求要点 | 调用者得到的结果 |
|---|---|---|
| `POST /v1/teams` | 成员文件、原始角色 ID 和职责文本 | 群 ID、Lead、成员快照与契约版本。导入前校验重复 ID、缺失提示词和无法解析的段落。 |
| `POST /v1/teams/{id}/messages` | 客户端请求键、正文、群聊或双方会话、可选点名和引用 | 已落库的消息 ID、顺序号。普通需求可先发言再登记目标。答复校验原问题与真人身份。 |
| `GET /v1/teams/{id}/snapshot`、`GET /v1/events?after=…` | 当前用户身份与上次快照游标 | 可见目标、问题、任务、版本及后续可见事件。重连可去重，游标失效时重新取快照。 |
| `GET /v1/sessions/{id}/turns` | 可访问的父执行会话。 | 已完成且可选的回合列表。 |
| `POST /v1/sessions/{id}/forks` | 父执行会话、显式回合 ID、活动目标、首次协商或既有任务范围、允许使用的版本和工具、联系人、结果接收者及请求键。 | 已持久建好的子会话、检查点和排队状态。发起人可在交接界面看到所选回合、材料和收件人。 |
| `POST /v1/proposals/{id}/confirm` | 已认证的承诺方和草案版本。修订草案另有任务与基础修订。 | 确认回执与仍待确认的人。另一方改写草案后，旧确认只对旧稿有效。有权正式成员通过正式写入登记已获全部确认的约定。 |
| `POST /v1/approvals/{id}/decision` | 操作参数摘要、答复、真人身份和请求键 | 仅该次动作的许可或拒绝及待办状态。推送批准绑定仓库、ref 与提交。 |
| `GET /v1/artifacts/{id}/versions/{v}`、`GET /v1/goals/{id}/report` | 获授权的读者、指定版本或目标 | 只读材料，或投影到该读者范围的报告与评测依据。 |

模型工具与 HTTP 共用一组应用处理器。宿主注入团队、正式成员或助手身份、当前会话、运行代次和请求键。工具返回资源 ID、产生的事件 ID、当前版本或稳定错误。HTTP 409 表示过期修订、重复键异义或状态冲突，422 表示输入不合法，404 用于调用者不可读的对象。预算或并发上限提供可观察的等待或终止原因。工具适配器把业务结果回送到原模型调用 ID。

## 持久记录与提交边界

| 记录组 | 关键字段或约束 |
|---|---|
| 身份、会话及历史 | 成员 ID 在群内唯一。每个会话有所有者、参与范围和运行代次。回合有序，保存角色输入、模型消息、工具调用与对应结果。含敏感材料的条目携带来源与授权范围。 |
| 检查点及子会话 | 检查点固定父执行会话和已完成回合末端，保存当时适用的任务修订和已发布材料引用。子会话保存检查点、父代理、活动目标及获准的首次协商或既有任务范围。子会话与首个待执行项在同一事务产生。 |
| 草案、确认与任务 | 首次草案关联活动目标和协商范围，修订草案另关联任务和基础修订。确认键为草案 ID、版本和承诺方。登记时重新校验当前草案版本、全部确认、写权限和适用的基础修订，在事务内登记唯一任务或下一修订。任务保存当前修订、派发者、负责人和主审。修订不可覆盖，依赖有向无环。 |
| 事件、收件与回执 | 业务事件按序追加。以事件、收件人、投递目的去重。幂等键按调用主体和业务操作隔离，同内容重放返回原资源，不同内容返回冲突。 |
| 交付和评测 | 产物版本关联作者、内容摘要、允许读者。提交关联任务修订、所交版本、证据和上次退回记录。审查指向确切提交。指标以原始布置消息、业务对象与服务端时间计算，登记前终止从原始消息查到终止事实。 |

每次业务写入在短事务里依次校验授权、幂等键、修订和前置状态，写记录、事件和待投递项后提交。网络调用、容器命令和长时间文件复制在事务外完成。发布先完整保存并校验字节，再登记版本。失败留下的暂存内容按引用清理。通知、目标清单及群计划从事件投影生成。

## 指定历史回合分支

1. 父代理在当前活动目标内选定首次协商或既有任务范围，并选择自己执行会话的一个已完成回合。宿主核对回合状态、工具、材料版本、联系人和结果接收者。回合尚未结束或材料不足时返回具体原因，父会话可以继续工作。
2. 宿主固定检查点，按当前工作范围、交接时的授权和读取时仍有效的授权筛选历史。工具调用与结果成组继承。若结果引用的材料受限，整组省略或只给已授权的替代材料。父会话后续发言独立追加。
3. 助手首次决策时读取历史、工作范围、可用版本及适用的当前有效修订。助手需要执行文件操作时使用私有可写空间，将授权版本导入为输入。文件内容取自固定版本，历史对话中的路径只作线索。
4. 运行时收到任务修订后定向通知仍参与此任务的分支。助手可返回材料或草案。有权正式成员在全部承诺方确认同一有效版本后登记任务或修订。已过期草案可对照当前修订产生新版，保留旧判断的依据。
5. 同一工作范围有效时可续问。首次协商登记、拒绝或撤回后结束。已登记任务通过显式授权向助手交接材料和工作。范围结束或撤权时停止相关执行和写入，后续读取重新检查权限，已公开采用的产物按自身版本和授权管理。

## 重启时如何决定下一步

| 中断点 | 恢复行为 | 核对证据 |
|---|---|---|
| 更新已提交，群通知尚未显示 | 重新投递同一事件，客户端按序号去重 | 任务修订、群通知和定向收件回执 |
| 分支已建，尚未完成首次调用 | 按建分支请求键返回同一子会话，领取原待办 | 父回合、子会话 ID 与首次运行记录 |
| 首次草案已提交，尚未登记任务 | 从持久草案恢复同一版本和确认状态。满足全部确认后由有权成员登记，已登记时重放返回同一任务 | 草案版本、承诺方确认、登记任务 ID 或待确认状态 |
| 模型请求已发出，返回状态不明 | 核对持久回合与已生效工具动作，隔离旧运行代次。能安全接续时从最近完整记录继续，其余显示待核对 | 请求摘要、工具回执、接续所用的回合 |
| 用户答复已到，服务随后重启 | 按问题 ID 读取唯一有效答复，清除对应阻塞，投递给原提问者 | 问题、答复消息与待办唯一键 |
| Git 推送超时 | 查验批准的目标 ref。新提交已可见则补回执，状态分叉或无法查询时转待核对 | 真人批准范围、推送操作 ID 与远端查询结果 |
| 任务或目标已结束，在途答复或执行结果随后到达 | 先检查当前关联与运行代次。仍关联有效工作的事项仅投递到有效范围。其余仅留历史或核对已经发起的外部动作 | 停止范围、有效关联、终止时间、迟到回执和冻结指标 |

本机运行模式从启动配置确定。正式模式校验课程端点和模型，认证或工具调用失败时显示原因。回归用 mock 模式在报告中单独标识。
