# 多智能体协作平台详细需求

确认状态为已定稿，设计完整度为设计完备。课程项目的全部功能在一个大版本中实现并交付，指定历史回合建分支属于必验能力。当前平台范围内的必要行为均已确定。正式课程提交及运行前仍有待确认的外部条件，见本文的评测与交付边界。

更新于 2026-11-22，上海时间。适用范围为单机课程平台的建组、委派、历史分支、工具执行、验收与连续任务评测。产品范围和课程约束继承[初步设计](../../preliminary-proposal.md)。业务对象的关系、状态和不变量维护在[领域模型](domain-model.md)，接口、存储与恢复规则见[运行时对接设计](runtime-contract.md)。

## 术语

| 术语 | 项目中的含义 |
|---|---|
| Lead | 接收未点名需求、维护项目分工、处理职责与能力缺口并向用户交付的正式成员。 |
| 工作分配契约 | 本团队对长期职责与交接边界的约定。 |
| 委托、草案与修订 | 委托是双方对具体交付的承诺。草案承载协商内容，生效后的每一次变更具有唯一修订号。 |
| 首次委托协商 | 在活动目标内，为尚未生效的一项工作约定交付、参与者与验收条件。协商有明确范围，正式登记时才产生任务 ID。 |
| 父代理与子代理 | 父代理派出助手、限定范围并负责上游交付。子代理在独立会话内执行有界工作，可提交材料和草案。 |
| 聊天线程与执行会话 | 聊天线程承载群聊或双方私聊。执行会话承载成员或助手的模型回合、工具记录与历史分支。 |
| 已完成回合 | 一次具有稳定起止边界的会话执行，模型消息、工具调用及对应结果已持久归档。 |
| 检查点与分支 | 检查点定位某个已完成回合末端的历史及材料引用。分支是从该检查点独立延续的子代理会话。 |
| 产物版本、提交、审查 | 版本固定交付内容。提交将版本与生效的任务修订及证据绑定。审查是主审对该提交作出的通过或退回决定。 |
| 经验采用 | 成员引用既有经验，实施可定位的后续行动，并记录其结果。 |
| 独立核查、重现 | 独立核查要求成员在获知对方结论前先形成判断。重现要求接收者用获准版本及说明独立得到约定结果。 |

## 项目交付行为

**建组和增员。** 用户导入角色清单，查看原始身份、职责、识别的 Lead 和成员名单。无明显 Lead 时由过渡 agent 创建 Lead 后退出。Lead 建立契约，按职责遗漏、能力缺口、待用户决定三种情况处理分工例外。若决定新增正式成员，先明确其工作边界、工作区和主会话，再向团队公布契约修订。新增成员的主代理享有与其他正式角色相同的任务创建和更新权限。样例加载器支持约定格式下的可变成员清单，格式不符应指出出错位置。首轮单独验证运行中增员。

**自主拆解、确认与交付。** 所有正式角色的主代理均可在授权范围内提出任务、调用 `assign_task` 创建任务及调用 `update_task` 登记修订。接手人可拒绝、反提议或指定依赖。承诺方确认同一草案版本后，正式成员登记有效委托或新修订，保留真实派发者与接手人。改变既有或拟任负责人、主审或其他成员的承诺时，由受影响的承诺方确认。子代理可提供材料和草案。成功更新在群内自动 `@Lead`，工作完成提交时同时提醒 Lead、派发者并送审。主审逐项对照承诺，只退回有证据的缺口。待复核的下游可定位所依赖的旧版。专家分歧可以通过共同接受一个交付方案解决，记录各方判断及证据。用户要求单一行动时由负责该决策的成员给出结论。

**群聊、私聊与人工决定。** 引用原问题的答复优先于点名，点名优先于默认 Lead。影响交付或验收的歧义若无法依据已有决定作可逆处理，成员先向用户澄清，可在目标登记前提问。受影响的工作暂停并释放执行槽，独立工作继续。引用答复仅解除对应问题的阻塞。人机及成员间的双方私聊按参与者读取，涉及私聊的进度在群内使用可公开的摘要。用户可用自由文本纠正假设。系统通知引用旧决定的负责人，由其报告哪些材料受影响。

**历史分支与助手协作。** 父代理可在当前活动目标内选择自己执行会话的任一可用已完成回合，并为助手指定首次协商或既有任务范围，写明目的、允许使用的版本和工具、可联系对象及结果接收者。派发方与接手方可各派助手起草或修订同一份约定，也可直接在指定范围内答疑和核查。所有承诺方确认同一版本后，由有权正式成员登记一项任务或下一修订。修订还须匹配当前基础修订。首次协商登记、被拒绝或撤回后结束，助手如需继续为生效任务工作，须经显式授权交接。父代理与助手能同时推进不同工作。并行取材、独立复算和在同一范围内续问由成员按需要选择。需要独立判断时，可以只提供原始材料和待核查问题。助手结果须保留来源范围，扩大受众时只交付获准内容。

**工具执行与外部授权。** 成员通过受控工具检索和取回资料，在获准的私有工作区读取、创建、修改或删除文件，运行与测试代码并创建 Git 提交。GitHub 推送须先获得真人明确批准，许可绑定仓库、目标 ref、提交 SHA 和动作。宿主区分待批、拒绝及许可范围不匹配。结果不明时按批准目标核对并留存回执。正式模式仅调用课程指定模型端点，离线回归显式使用 mock。

**结案与终止。** Lead 组织确认目标验收条件，将必需交付列为显式条目，关联负责交付的任务与当前审查。变更时保留验收约定的修订。必需交付通过当前验收、相关阻塞解除且最终版本可读后，Lead 交付并关闭目标。任务或目标终止时，停止只服务于该范围的待办和助手，关闭相关未登记草案与待答问题，停止该范围内尚未发起的外部动作。仍服务于其他有效工作的事项保留其有效关联。迟到答复和执行结果按可见范围归档或用于核对已发起的外部动作，已终止工作和冻结计数保持封存。活动目标结束后，平台通知 Lead。Lead 按队列顺序从满足前置条件的目标中激活下一项。

**个人经验与跨题延续。** 每名正式成员有独立持久的经验记录和检索能力，由成员根据实际证据决定记录哪些经验。经验正文默认由作者读取，授权助手可在指定委托内读取显式交接的条目。向其他成员分享时按来源权限作显式交接。报告区分写入、检索、采用和可观察结果，可展示成员因上一题的教训改用一手证据的那次行动。同一群顺次接两题，分别计时与验收。软件组第二题从第一题真实版本和预约记录继续，新闻组针对新主张重新取证，基金组将受众从个人客户切换到基金团队。独立复核和接收者重现属于可选工作方法。

## 验收场景

| 场景 | 操作与应观察到的证据 |
|---|---|
| 指定旧回合建分支 | 父会话完成三轮，各写入可区分的事实。选择第二轮创建助手，核对助手取得前两轮获准材料及所选版本；第三轮材料只在显式授权交接后可读。父、子分别继续一轮，能独立定位两条历史。重复同一建分支请求只生成一个子会话。 |
| 助手参与首次委托协商 | 在无生效任务的活动目标中，派发方和接手方从各自已完成回合派出助手。助手在限定范围内共享材料并交回草案。一方确认后改写条款，重启仍可查看各版本的确认记录。承诺方全部确认新版后，重复登记只产生一个任务 ID 和一次有效派发，旧版及被拒草案不计入分母。 |
| 跨参与者隔离 | 同一父代理拥有群消息及与用户的受限私聊。向助手交付群任务，分别从模型输入、附件工具、检索、事件回放、记忆及导出检查可见性。用一个获授权版本作正例，避免将全部拒绝误判为隔离通过。 |
| 草案过期 | 助手基于修订 3 协商期间，正式成员使修订 4 生效。旧稿返回时显示冲突与差异，主代理可请助手更新并重新送审。只在双方接受有效草案后登记新修订与群通知。 |
| 非阻塞答疑 | 派发者的助手在指定版本上答疑，同时派发者本人有另一任务在推进。用回合时间、会话 ID 和答复引用证明执行有重叠，采用结果可追到父代理。 |
| 多问题与重启 | 一名成员在群里提问，另一名成员私聊用户。重启后引用其中一个问题答复。检查未答问题仍在、私聊仅双方可见、就绪的独立任务仍可领取。 |
| 终止时仍有在途工作 | 终止一个有待答问题、未确认草案和执行中助手的目标。再提交迟到答复与助手结果，检查历史和外部回执可追溯，待办未恢复，成绩仍等于终止时的冻结记录，独立的排队目标可继续。 |
| 动态增员与自主委派 | 初次遇到确凿能力缺口时由 Lead 增员并修订契约。由新增角色的主代理在同版确认后创建任务并登记修订，核对其他正式角色具备同样的任务写入能力，同时检查目录隔离、确认记录和交接材料。 |
| 必需交付与下一目标 | 让一个必需交付待验，检查 Lead 无法成功结案。通过当前审查后，关闭目标并检查 Lead 收到通知，由 Lead 激活排队中满足前置条件且顺序最早的目标。 |
| 局部返工 | 同目标含两个模块。主审退回其中一个 v1，执行者用原任务交 v2，未受影响模块保留通过。过期 v1 验收不能关闭仍待验的目标。检查通知收件人、两版证据及计数。 |
| 真实模型与外部工具 | 课程端点在第二次调用实际使用第一次工具返回值。第三名成员无法读未发布草稿，获准取得指定版本后能在私有卷测试。审批拒绝或推送结果未知时显示实际状态。 |
| 授权绑定与过期 | 真人批准仓库、分支和提交 SHA 后改变任一项，检查宿主仅接受匹配批准范围的操作。两次提交同一有效请求应得到相同动作回执。 |
| 记忆与两题连续 | 选择 T1 一条有来源的经验，在 T2 逐步定位检索、采用、行为及观察结果。用另一成员和显式获准的助手分别验证正文的读取边界。报告保留无改善和失效条件。涉及提升的因果判断须有独立对照依据。 |
| 指标可重算 | 在两项生效委托后新增第三项，另留一份未接受草案，再将某委托退回重交。终止时若两项已通过，子任务完成率应为 2/3。保留三个任务 ID、最终修订和审查引用。 |
| 登记前等待纳入评测 | 用户发出明确布置，Lead 先澄清后登记。重放同一原始消息，核对只计一个目标，历时从布置消息落库开始并包含澄清等待。若用户在登记前终止该目标，报告仍保留该目标、终止时间和原因。 |

演示优先选择一次真实发生的“同伴提供证据，负责人据此改变行动”的事件。成员可选择缺口认领、双份取证、具体样例提问或接收者重现。重大分歧按各方接受的交付条款记录，补充用户口径后允许未受影响的工作继续。助手在仍有效的协商或委托内可续问，结束后归档供追溯。跨题使用显式交接的产物、可共享决定和授权经验。反复出现的长期职责交给 Lead 评估增员。

## 评测与交付边界

目标按用户的原始布置消息去重，从消息落库开始计时，包含登记前澄清和排队等待，最终交付或终止时停止，另列等待真人区间。目标分母为全部用户布置的目标，含登记前终止的布置。同一目标的后续补充关联原布置消息，普通交流按消息记录。分子为满足有效验收条件且已交付的目标。子任务分母为期间全部已确认生效的唯一任务，新发并登记的任务纳入集合，返工沿用原任务 ID。分子为目标结束时按当前条件通过的任务。目标结束时冻结编号集合和原始计数。分母为零记不适用。超时、失败、未完成和外部质量评阅均单列，正式报告引用真实课程模型、运行模式和证据清单。

按场景保存有权限查阅的完整对话、产物与验收引用。课程常规文档按 Markdown 或纯文本交付。首轮验收、团队贡献历史及课程展示要求已在初步设计中列明。[课程原文](../../raw/basic_requirement.md) · [初步设计第 8、9 节](../../preliminary-proposal.md)

- **U-001 基金第二题正式提交格式。** 样例准备可逐页演示的 HTML 和 Markdown 内容稿，正式提交以课程组口径为准。待确认项影响正式交件的格式选择。[基金第二题题面](<../../../test samples/scenario_3_securities_fund 2/03_task_2.md>) · [课程原文](../../raw/basic_requirement.md)
- **U-002 正式评测输入与端点条件。** 闭集实际输入、发放与提交日程、教师端点配额在发放后核实，用于安排正式评测和配置运行。端点实际工具能力以联调为准。[课程原文](../../raw/basic_requirement.md) · [联调待验证项](#待验证项)

## 开源复用与本组实现边界

本节为规格设计提供选型依据。直接采用项沿用单机 Python、FastAPI、SQLite、Docker 和 Git 的运行时方案。可选依赖按对应模块的验证结果决定。调研截至 2026-11-22，证据来自上游文档、源码和许可证，实际版本以联调结果为准。[运行时对接设计](runtime-contract.md)

### 待验证项

- **课程端点与工具循环。** 使用课程发放的端点、模型和凭据，确认第二步调用实际使用第一步工具返回值，核对调用 ID、实际请求目标和正式模式的报错。按拟采用模式确认参数 Schema 与历史回传要求，核实 HKGAI 课程模型是否支持原生工具调用。
- **历史分支与并行隔离。** 对照指定旧回合建分支、跨参与者隔离及非阻塞答疑场景，核对第三轮历史、私聊和私有草稿的读取边界，并用获准版本作正例。如评估以 Codex App Server 替换单角色工具循环，使用候选版本复验这些场景、课程模型工具闭环及重启恢复。Deep Agents 异步委派需要兼容 Agent Protocol 的服务，OpenHands 当前的子会话创建沿用父工作目录，试用时需分别核对独立运行与工作区隔离。[Deep Agents 异步子代理](https://docs.langchain.com/oss/python/deepagents/async-subagents) · [OpenHands 委派源码](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-tools/openhands/tools/task/manager.py)
- **持久化与联调。** 验证断线按权限补发和游标失效、并发认领与草案过期、重启后引用答复只恢复对应工作、推送结果不明时核查远端，以及依据冻结记录重算 `2/3`。根据部署端读写测试决定 SQLite 日志模式。
- **可选依赖与原型。** FTS5 待验证部署可用性、样例用语命中及按成员授权过滤。SearXNG 待验证实例是否启用 JSON、来源可追溯性和真实查询可用性。队友设计所列 `harness/` 原型文件待定位到具体分支或提交后核对。
