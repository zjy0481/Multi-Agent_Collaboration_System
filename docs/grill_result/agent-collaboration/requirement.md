# 多智能体协作平台首版详细需求

确认状态为已定稿，设计完整度为设计完备，适用于下述首版需求范围。历史回合分支由项目组长明确纳入首版，异常处理、权限校验和评测细节由主代理按本轮授权确定。基金题的最终提交格式仍待课程组通知。

更新于 2026-11-22，上海时间。适用范围为单机课程平台的建组、委派、历史分支、工具执行、验收与连续任务评测。产品范围和课程约束继承[初步设计](../../preliminary-proposal.md)。业务对象的关系、状态和不变量维护在[领域模型](domain-model.md)，接口、存储与恢复规则见[运行时对接设计](runtime-contract.md)。

## 术语

| 术语 | 项目中的含义 |
|---|---|
| Lead | 接收未点名需求、维护项目分工、处理职责与能力缺口并向用户交付的正式成员。 |
| 工作分配契约 | 本团队对长期职责与交接边界的约定。 |
| 委托、草案与修订 | 委托是双方对具体交付的承诺。草案承载协商内容，生效后的每一次变更具有唯一修订号。 |
| 父代理与子代理 | 父代理派出助手、限定范围并负责上游交付。子代理在独立会话内执行有界工作，可提交材料和草案。 |
| 已完成回合 | 一次具有稳定起止边界的会话执行，模型消息、工具调用及对应结果已持久归档。 |
| 检查点与分支 | 检查点定位某个已完成回合末端的历史及材料引用。分支是从该检查点独立延续的子代理会话。 |
| 产物版本、提交、审查 | 版本固定交付内容。提交将版本与生效的任务修订及证据绑定。审查是主审对该提交作出的通过或退回决定。 |
| 经验采用 | 成员引用既有经验，实施可定位的后续行动，并记录其结果。 |
| 独立核查、重现 | 独立核查要求成员在获知对方结论前先形成判断。重现要求接收者用获准版本及说明独立得到约定结果。 |

## 首版交付行为

**建组和增员。** 用户导入角色清单，查看原始身份、职责、识别的 Lead 和成员名单。无明显 Lead 时由过渡 agent 创建 Lead 后退出。Lead 建立契约，按职责遗漏、能力缺口、待用户决定三种情况处理分工例外。若决定新增正式成员，先明确其工作边界、任务更新权限、工作区和主会话，再向团队公布契约修订。样例加载器支持约定格式下的可变成员清单，格式不符应指出出错位置。首轮单独验证运行中增员。

**自主拆解、确认与交付。** 成员可从用户目标中提出可检查的子任务。接手人可拒绝、提出新范围或指定依赖。接受同一草案后登记有效委托，保留真实的派发者与接手人。任何初始正式角色可在授权关系内调用 `update_task`，子代理仅能提交草案。成功更新在群内自动 `@Lead`，工作完成提交时同时提醒 Lead、派发者并送审。主审逐项对照承诺，只退回有证据的缺口；变为待复核的下游可定位所依赖的旧版。专家分歧可以通过共同接受一个交付方案解决，记录各方判断及其证据。用户要求单一行动时由负责该决策的成员给出结论。

**群聊、私聊与人工决定。** 引用原问题的答复优先于点名，点名优先于默认 Lead。未登记目标也能先向人澄清。人机及成员间的双方私聊按参与者读取，涉及私聊的进度在群内使用可公开的摘要。用户可用自由文本纠正假设或批准特定外部动作。系统通知引用旧决定的负责人，由其报告哪些材料受影响。独立工作继续执行。

**历史分支与助手协作。** 父代理可以选择本会话的任一可用已完成历史回合，指明目的、允许使用的版本、可联系对象和交付目标。父代理与助手能同时推进不同任务。发起方可派助手答疑，接手方可派助手核查，双方可直接在本次委托范围内求证。并行取材、独立复算及带着同一材料继续追问由成员按需要选择。需要独立判断时，可以只提供原始材料和待核查问题。助手遇到新承诺先交回草案，两方主代理审查同一版本后登记。助手从已授权材料形成的结果须保留来源范围，向更大受众发布时只交付获准内容。

**跨题延续。** 同一群顺次接两题，分别计时与验收。软件组第二题从第一题真实版本和预约记录继续，新闻组针对新主张重新取证，基金组将受众从个人客户切换到基金团队。每人可以记录有证据的经验，报告区分写入、检索、采用和可观察结果；可展示成员因上一题的教训改用一手证据的那次行动。独立复核和接收者重现属于可选工作方法。

## 验收场景

| 场景 | 操作与应观察到的证据 |
|---|---|
| 指定旧回合建分支 | 父会话完成三轮，各写入可区分的事实。选择第二轮创建助手，核对助手取得前两轮获准材料及所选版本；第三轮材料只在显式授权交接后可读。父、子分别继续一轮，能独立定位两条历史。重复同一建分支请求只生成一个子会话。 |
| 跨参与者隔离 | 同一父代理拥有群消息及与用户的受限私聊。向助手交付群任务，分别从模型输入、附件工具、检索、事件回放、记忆及导出检查可见性。用一个获授权版本作正例，避免将全部拒绝误判为隔离通过。 |
| 草案过期 | 助手基于修订 3 协商期间，正式成员使修订 4 生效。旧稿返回时显示冲突与差异，主代理可请助手更新并重新送审。只在双方接受有效草案后登记新修订与群通知。 |
| 非阻塞答疑 | 派发者的助手在指定版本上答疑，同时派发者本人有另一任务在推进。用回合时间、会话 ID 和答复引用证明执行有重叠，采用结果可追到父代理。 |
| 多问题与重启 | 一名成员在群里提问，另一名成员私聊用户。重启后引用其中一个问题答复。检查未答问题仍在、私聊仅双方可见、就绪的独立任务仍可领取。 |
| 动态增员与自主委派 | 初次遇到确凿能力缺口时由 Lead 增员并修订契约，后来另一成员可据此直接委派同类工作。核对新增角色的权限、目录隔离、确认的委托和交接材料。 |
| 局部返工 | 同目标含两个模块。主审退回其中一个 v1，执行者用原任务交 v2，未受影响模块保留通过。过期 v1 验收不能关闭仍待验的目标。检查通知收件人、两版证据及计数。 |
| 真实模型与外部工具 | 课程端点在第二次调用实际使用第一次工具返回值。第三名成员无法读未发布草稿，获准取得指定版本后能在私有卷测试。审批拒绝或推送结果未知时显示实际状态。 |
| 授权绑定与过期 | 真人批准仓库、分支和提交 SHA 后改变任一项，检查宿主仅接受匹配批准范围的操作。两次提交同一有效请求应得到相同动作回执。 |
| 记忆与两题连续 | 选择 T1 一条有来源的经验，在 T2 逐步定位检索、采用、行为及观察结果。报告保留无改善和失效条件。涉及提升的因果判断须有独立对照依据。 |
| 指标可重算 | 在两项生效委托后新增第三项，另留一份未接受草案，再将某委托退回重交。终止时若两项已通过，子任务完成率应为 2/3。保留三个任务 ID、最终修订和审查引用。 |

演示优先选择一次真实发生的“同伴提供证据，负责人据此改变行动”的事件。成员可选择缺口认领、双份取证、具体样例提问或接收者重现。重大分歧按各方接受的交付条款记录，补充用户口径后允许未受影响的工作继续。助手会话在当前目标内可续问，目标关闭后归档供追溯。跨题使用显式交接的产物、可共享决定和授权经验。反复出现的长期职责交给 Lead 评估增员。

## 评测与交付边界

目标从用户布置开始计时，最终交付或终止时停止，另列等待真人区间。子任务分母为期间全部已确认生效的唯一任务，运行中允许新发现的工作进入集合，返工只增修订。分子为按当前条件通过的任务。目标分母为全部用户布置目标，分子为满足有效验收条件且已交付的目标。终止时冻结编号集合和原始计数。分母为零记不适用。超时、失败、未完成和外部质量评阅均单列，正式报告引用真实课程模型、运行模式和证据清单。

按场景保存有权限查阅的完整对话、产物与验收引用。基金第二题准备 HTML 演示与 Markdown 内容稿，正式提交按课程组口径选择。未知闭集的输入格式和教师端点配额在发放后核实。首轮验收、团队贡献历史及课程展示要求见[初步设计第 8、9 节](../../preliminary-proposal.md)。
