# 多智能体团队可以怎样协作

> 本文记录早期讨论或设计输入。当前实施与联调请使用[多智能体协作平台初步设计](../../preliminary-proposal.md)。

协调者、工作分配契约、可协商与修订的委派，以及专业分歧的交付方式已定稿。更新于 2026-11-22，上海时间。

## 探索起点

老师给出成员身份和两道连续的题，成员与真实用户协商分工、验证方法与完成条件。已有方案支持群聊、私聊、委派、版本交接与个人经验。这轮讨论关注成员遇到什么情况会改变工作方式，以及这种改变能否从实际产物中看出来。[样例说明](<../../../test samples/README.md>) · [初步方案](../../preliminary-proposal.md)

## 候选方向

| 方向 | 成员可以怎样行动 | 适合观察什么，代价在哪里 |
|---|---|---|
| A．遇到分歧时独立核查 | 新闻组判断 AI 写作检测器是否可靠。记者找支持证据，核查员在看到记者结论前自行选材料、写下判断。两人随后对照适用人群、误判与证据缺口，编辑据此修稿。 | 看独立工作是否发现首稿遗漏的限定条件，以及它是否改变最终报道。多花一轮取证，适合团队认为有争议的主张。 |
| B．围绕缺失的证据认领工作 | 软件看板已能画图，但“取消后重新预订应算几次”仍缺依据。任一成员都能公开指出缺口。手头有第一题真实记录的人举例，能复算的人接手验证。也可用于新闻组认领缺来源的断言。 | 看谁凭已有材料主动加入，以及哪条证据使问题得以关闭。共享内容只包括显式发布的材料。缺口过细会使协调比实际工作更费力。 |
| C．让用户通过具体样例决定 | 先用一条“预约两小时后取消”的记录，向用户展示“累计预订时长为两小时”和“实际占用时长为零”分别能回答什么。用户可以选一个、要求两个都展示，或提出另一口径。 | 看一次答复能否同时指导开发、测试和说明文档。成员需先做一份小样，并给用户留出重新定义问题的空间。 |
| D．让经验带上失效条件 | 基金研究员把“用原始披露核对公司说法”与“向这位客户解释风险时使用的例子”分开。第二题面向基金团队时，成员说明为何沿用前一种方法，又为何舍弃后一种表达。 | 看第二题究竟改了哪次检索、哪处产物或哪项决定。引用上题经验却没有行为变化，也值得记录。逐条说明会增加负担，可先关注影响交付的经验。 |
| E．让同伴从交付物重现结果 | 软件组让另一成员从指定提交和交付说明启动预约系统，亲自创建、取消再预订。新闻组让编辑仅凭已交付材料找到支持某句话的原始段落。 | 看接收者能否独立复现，以及首次失败指出了什么遗漏。成本是另一人的执行时间，可聚焦最关键的一项承诺。 |

A 和 B 可以形成两种不同的协作节奏。已经明确缺哪项材料时，公开求证让掌握材料的人加入。连问题本身都存在争议时，先让两人分别判断更值得尝试。C 关注用户能否做出有效决定，D 关注旧经验能否恰当地影响新任务，E 关注交出去的结果能否被下一人使用。团队可以在同一场景中组合这些做法。

## 已敲定的协调者设计

项目组长确认 coordinator（协调者）常驻项目，建组时创建业务成员，与用户建立工作分配契约。契约约定一类交付物由谁牵头、谁可以协作。归属明确时，成员直接委派。多名成员都能承担或找不到合适成员时，协调者负责落实工作归属。

1. 缺职责时，指定有能力的成员牵头。每次例外记录理由，能指导后续分工的裁决写入契约，因临时负载产生的指派保留为个案。
2. 缺能力时，判断新增成员能提供的专长、工具或独立复核价值。决定增员后，将新成员的职责及与原成员的交接边界写入契约。
3. 缺用户决定时，指定成员向用户问清目标或业务口径，得到答复后继续分派。

项目组长已明确，评测允许动态增员，每名业务成员也可以使用子代理。子代理的协作方式留作独立设计议题。既有约束包括使用课程允许的模型、逐成员隔离、用户真实参与，以及同组跨题延续。

## 接下来可探索的方向

专业分歧的交付原则已在下文定稿。表中示例供讨论。

| 方向 | 用课程场景比较做法 | 取舍 |
|---|---|---|
| 用户答复如何影响已经开始的工作 | 开发和测试已按各自理解计算预约时长。用户澄清取消记录要单列。可以在群里公布决定，由成员各自判断影响，也可以让采用旧口径的图表作者和测试作者分别回报“需修改”或“仍适用”。若澄清来自私聊，先由用户确认可以共享的业务表述。 | 前者只需一次通知，后者多一次反馈，可以看清哪些旧结果仍然有效。 |
| 团队如何带着专业分歧交付 | 半导体研究员与风险经理认同同一批数据，对下一年需求的判断不同。基金经理可以选用一项假设并说明理由，也可以给出两种情景和区分它们的观察指标。 | 单一判断便于行动，情景分析能让读者在新数据出现后重新判断。两者都可保留专业意见的来源。 |
| 新成员如何接上已经进行的工作 | 新闻组中途增加统计背景的成员。可以由记者交付主张、论文和当前争议，也可以先发原始主张和来源，让新成员独立写下判断，再对照已有讨论。材料均限定在可分享范围。 | 带上争议可减少重复劳动，先给原始材料则保留一次独立发现问题的机会。 |

### 自主拆解、协商与委派

项目组长已敲定：委派是一项可以协商、也可以修订的约定。提出方和接收方可以商定交付内容，并在任务条件变化时重新商定。口径变更和新成员加入是这一原则的两个应用场景。以下具体做法仍为候选。

- 任何成员都能从用户目标中提出可独立检查的交付物，说明谁要使用它、如何判断可用。其他成员可以认领、提出不同拆法、指出重复或缺失。任务提出者可按工作分配契约邀请同伴，接收者可以接受、拒绝或提出接手条件。双方达成一致时记录实际负责人、输入、交付物和验收约定。接手者仍可继续委派局部工作，对自己的上游交付负责。
- 成员标明工作所采用的用户决定和输入版本。新决定到来时，平台据此通知已知受影响者，在原可见范围内保留讨论入口。成员自行判断需要改动什么，可以只更新验收条件，也可以另提任务。引用关系可能漏项，其他成员也能主动报出影响。
- 新成员接手同一种委派。对方提供本次目标、可共享的依据、待解决的问题及结果交给谁。接手续作时可补当前版本和已有判断，做独立复算时可先给口径和原始记录。接收者可要求补充材料。
- 演示可选一条实际发生的委派，展示原提议、接收者提出的修改、最终交付，以及用户澄清后团队调整了哪部分工作。平台记录协商结果及其变化，具体拆法由本题成员提出。

### 专业分歧中的协商（已定稿）

项目组长确认把同一协商机制用于专家意见相左的情形。双方可以认可同一份交付约定，同时保留各自的专业判断。平台记录每人接受的具体提议。若任务要求单一行动建议，由承担该决策职责的业务成员给出建议和理由。例如，研究员与风险经理可分别写出自己对订单增长的解释，共同交付两种情景及后续观察指标。

## 业务成员怎样使用子代理

这一节保留子代理专题在发散阶段的讨论。后续定稿中，Lead 承担动态增员职责，从指定历史回合创建子代理分支已纳入课程项目交付范围。[详细需求](requirement.md)

本轮用一个责任问题区分这两种需要。假设测试工程师已经接下预约看板的统计验收，他可以请助手复算一批记录，并对最终核验结论负责。若多个成员需要直接向某人委派统计工作，并希望此人持续负责统计口径，则可以由协调者评估新增业务成员。

### 委派双方各自派出子代理

用户提出一种通用协作方式。A 将工作委派给 B 后，可以派出一个继承自己相关上下文的子代理，为这次交接持续答疑，随后 A 去做其他工作。B 也可以派出子代理承担已接任务中的一部分。B 或其子代理可以就这次任务直接联系 A 指定的子代理。两方按需要分别决定是否派出助手。

例如 B 的助手核对某个交付版本时，A 的助手可以说明当时采用的假设并指出原始依据。若发现该假设与用户的新决定冲突，双方可以继续不受影响的工作，将需要重新商定的事项交回有权决定的成员。

助手建议按交接时点继承本任务相关且获准共享的上下文。此后影响这项委托的修订定向送达，避免子代理沿用旧决定。可将问题留在本次委托中，收到时唤醒答疑方，结束时将影响交付的结果回报父代理。

### 在指定回合分支，异步协商委托（候选）

用户提出由子代理异步起草和协商委托，也可商谈已有委托的修订，待草案准备好再交主代理审查确认。双方各派助手时，可以从各自主代理选定的已完成回合创建会话分支，在分支中保留截至该点获准继承的历史。完整历史均可授权时，可以整段继承。双方互相交换的是为这次协商发送的消息和材料，各自的私聊仍遵守原可见范围。

本轮把可再次定位的会话状态称为“会话检查点”（checkpoint），把从该点创建一条独立延续的会话称为“分支”（fork）。若检查点需要重现当时看到的文件，可另行引用文件版本或快照。运行时如何提供这些能力仍待验证。

建议分支交回拟议条款、相对现行委托的改动和待决定项。每位主代理确认自己承担的承诺。修订在确认前继续沿用现行约定，若现行版本已经变动，先核对差异再确认。分支里的讨论可供追溯。

### 子代理承担的工作示例

| 用法 | 委托、返回及采用 | 代价 |
|---|---|---|
| 并行取材 | 基金研究员分别交给两个助手一批公司披露。助手返回原文出处、日期与数字口径，研究员统一期间和单位后写行业分析。 | 输入适合拆开，汇总检查要计入研究员的工作。 |
| 独立复算 | 测试工程师只给助手预约记录、日期范围和已确认的取消规则。助手交回逐笔计算，测试工程师再与看板对照。 | 两个结果要能追到各自的方法。同一模型得出相同数字，仍需核对原始记录。 |
| 带着同一材料连续追问 | 事实核查员请一个助手读检测器论文，先找样本来源，再根据反馈追问阈值和误判范围。该助手在同一题里保留此前读到的段落。 | 省去重复阅读，也可能沿用第一次的误解。每项关键结论附原文位置有助于核查。 |

### 子代理的责任与待选边界

本轮暂称派出子代理的业务成员为“父代理”。父代理决定何时调用、提供本次所需且获准分享的材料、检查结果并向团队交付。子代理在自己的执行空间工作，本次委托可指定对方的答疑联系人。团队交付保留对所采用结果的引用，便于查到谁使用了哪批材料、完成了哪部分工作。

**谁需要直接联系这个子代理？** 若多个成员开始反复向同一助手提问，可比较由父代理转交、在本次委托范围内允许同伴直接追问、交由协调者设为正式成员三种做法。可用一次具体交接讨论消息经过谁、最终由谁签收。

**一项委托完成后，值得保留什么？** 可只保留可复核的结果，也可在同一题内保留助手会话供后续追问。两种做法都可由父代理决定哪些经验值得带到下一题。

## 术语

本轮所说的“独立核查”指两位成员在看到彼此结论前分别形成判断。“重现”指接收人使用获准交付的材料独立得到约定结果。这两个用语暂存于此，供讨论时引用。

## 建议收敛问题

- **演示中，观众看到哪一个瞬间，会相信这个团队确实需要多个成员？** 可以是同伴推翻首稿的一句结论，也可以是接收人在独立运行时发现作者遗漏的步骤。
- **项目契约要预先约定哪些协作方式，哪些交给接手的成员现场决定？** 例如“核查找谁”可在建组时确定，“是否先独立判断”既可成为本项目的一条约定，也可由核查员按具体主张决定。
- 若考虑经验复用，什么行为证据足以说明旧经验帮到了第二题，哪些情况只宜记录为观察？
